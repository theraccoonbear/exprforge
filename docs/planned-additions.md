# `letIn`, `cmp`, `select`

Two AST node types that extend the expression model without introducing
control flow. **Status: implemented** — this doc is kept as the design
rationale (especially the `select` safety caveat), not a spec to follow
literally. Three things landed differently than described below, all
found by actually compiling the emitted output:

- **`select`'s default ternary is not universal.** Go has no ternary
  operator at all (`if` is a statement, not an expression) and Rust uses
  `if`-as-expression instead of `cond ? a : b`. Both needed their own
  `emitSelect` override, same idea as QB64's — the "Default ternary (JS,
  C, Go, Java, Rust)" framing below is wrong; it's really JS/C/Java only.
- **Go rejects unused locals at compile time**, not just with a warning.
  A shared let-chain can bind more names than one function's body reads
  (see `samples/spline-frame.js`'s `mfLetChain`/`apLetChain` — e.g. a
  single-component function only returns one of `ux`/`uy`/`uz`). Go's
  `formatFunction` blank-discards every binding unconditionally
  (`_ = name`) to compile regardless.
- **`safeDiv` in the actual sample doesn't divide by the guarded value
  directly.** Per the safety caveat below, it clamps the denominator with
  its own nested `select` first (falls back to a literal `1`), so the
  division never sees a near-zero value on any target — not just on the
  five that happen to short-circuit.

## Motivation

The current four node types (`num`, `var`, `bin`, `call`) handle polynomial
arithmetic cleanly. Two things they can't express efficiently:

1. **Reused subexpressions.** Normalizing a 3D vector requires `sqrt(x²+y²+z²)`
   once, then dividing each component by it. Without a local binding you emit
   the sqrt call three times — one per component.

2. **Conditional values.** Gram-Schmidt frame construction must choose a
   `worldUp` vector based on whether the tangent is near-vertical (`|ty|>0.98`).
   That's a value selection, not a branch — it belongs in the expression, not
   around it.

Both stay within the expression model. Neither requires loops or statements.

## Addition 1 — `letIn(name, valueNode, bodyNode)`

### Node shape

```js
{ type: "let", name: string, value: Node, body: Node }
```

### Builder (ast.js)

```js
function letIn(name, value, body) {
    return { type: "let", name, value, body };
}
```

### Let-lifting utility (ast.js)

Before emission, all `let` nodes are lifted out of the tree into a flat
ordered list of `(name, Node)` pairs. The tree is then free of `let` nodes,
and every `v(name)` that referenced a binding becomes a plain variable
reference pointing at a local already declared above it.

```js
// Returns { bindings: [{name, node}], body: Node }
// bindings is in dependency order — safe to emit top-to-bottom.
function collectLets(node) {
    const bindings = [];

    function walk(n) {
        if (n.type === "let") {
            const { bindings: inner, body: val } = collectLets(n.value);
            bindings.push(...inner);
            bindings.push({ name: n.name, node: val });
            return walk(n.body);
        }
        if (n.type === "bin")    return { ...n, left: walk(n.left), right: walk(n.right) };
        if (n.type === "call")   return { ...n, args: n.args.map(walk) };
        if (n.type === "select") return { ...n,
            then: walk(n.then), else: walk(n.else),
            cond: { ...n.cond, left: walk(n.cond.left), right: walk(n.cond.right) },
        };
        return n; // num, var
    }

    const body = walk(node);
    return { bindings, body };
}
```

### Emitter base changes (emitters/base.js)

`emitFunction` calls `collectLets`, emits each binding's value string, then
passes the lifted body and the binding list to `formatFunction`:

```js
emitFunction(fn) {
    const { collectLets } = require("../ast.js");
    const { bindings, body } = collectLets(fn.body);
    const letBindings = bindings.map(({ name, node }) => ({
        name,
        valueStr: this.emitExpr(node),
    }));
    const bodyStr = this.emitExpr(body);
    return this.formatFunctionImpl(fn, bodyStr, letBindings);
}
```

`letBindings` is a new third argument to every `formatFunction` config
callback. It is an empty array when the expression has no `let` nodes, so
existing emitters that ignore the third argument continue to work unchanged.

### Per-emitter formatFunction updates

Each emitter prepends the bindings as local variable declarations.

## Addition 2 — `cmp(left, op, right)` + `select(cond, then, else)`

### Node shapes

```js
{ type: "cmp",    op: ">" | "<" | ">=" | "<=" | "==" | "!=", left: Node, right: Node }
{ type: "select", cond: CmpNode, then: Node, else: Node }
```

`cmp` is only valid as the `cond` of a `select` — it is not a general boolean
expression and should not appear elsewhere in a tree.

### Builders (ast.js)

```js
function cmp(left, op, right) {
    return { type: "cmp", op, left, right };
}

function select(cond, thenNode, elseNode) {
    return { type: "select", cond, then: thenNode, else: elseNode };
}
```

### ⚠️ Both branches are always evaluated

`select` is a *value* expression, not a branch. Every emitter evaluates both
`then` and `else` before selecting between them. **Do not use `select` to
guard against division by zero or other undefined operations.** The safe
pattern is to ensure `letIn` bindings before the `select` only contain
operations that are always defined, and to put any division outside the
select where the denominator is already known safe. If you need a true guard,
keep it as a hand-written `If/Then/Else` in the wrapper calling the generated
function.

### Emitter base changes (emitters/base.js)

Add `select` and `cmp` case handling to `emitExpr`, and a default ternary
`emitSelectImpl` / override hook:

```js
// In constructor:
this.emitSelectImpl = config.emitSelect
    ? config.emitSelect.bind(this)
    : this._defaultSelect.bind(this);

// In emitExpr switch:
case "select": {
    const thenStr = this.emitExpr(node.then);
    const elseStr = this.emitExpr(node.else);
    return this.emitSelectImpl(node.cond, thenStr, elseStr);
}

// Default ternary (JS, C, Go, Java, Rust):
_defaultSelect(condNode, thenStr, elseStr) {
    const L = this.emitExpr(condNode.left);
    const R = this.emitExpr(condNode.right);
    return `((${L} ${condNode.op} ${R}) ? ${thenStr} : ${elseStr})`;
}
```

### QB64 emitter override (emitters/qb64.js)

QB64 has no ternary operator. Comparison operators return `-1` (true) or `0`
(false). The algebraically equivalent expression using that convention:

```
result = (-1 * then) * cond + else * (1 + cond)
```

When `cond = -1` (true):  `(-1 * then) * -1 + else * 0 = then`  ✓  
When `cond =  0` (false): `(-1 * then) *  0 + else * 1 = else`  ✓

Add to the QB64 emitter config:

```js
emitSelect: function(condNode, thenStr, elseStr) {
    const L = this.emitExpr(condNode.left);
    const R = this.emitExpr(condNode.right);
    const cond = `(${L} ${condNode.op} ${R})`;
    return `((-1# * ${thenStr}) * ${cond} + ${elseStr} * (1# + ${cond}))`;
},
```

## Conformance test additions (test/conformance.test.js)

Add a test that exercises both features together — a normalization expression
where the length is computed once via `letIn` and the result is used in the
body, with a `select` choosing between the normalized value and a safe
fallback:

```js
// normalize(x, y, z) → x component, safe fallback 0 when len < ε
const EPS = num(1e-9);
const normalizeXAst = {
    name: "normalizeX",
    params: ["x", "y", "z"],
    body: letIn("len",
        call("sqrt", add(mul(v("x"),v("x")), mul(v("y"),v("y")), mul(v("z"),v("z")))),
        select(cmp(v("len"), ">", EPS), div(v("x"), v("len")), num(0))
    ),
};
```

Verify JS emitted output matches C emitted output for a sweep of inputs
including the near-zero case.
