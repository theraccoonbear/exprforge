# exprforge v0.2.0 — Standard Math Utilities

**Status: implemented** — this doc is kept as the design rationale, not a
spec to follow literally; see the "Resolved" section at the bottom (was
"Open questions before cutting the release") for how the three open
questions landed, plus one thing found only by actually running the
conformance suite:

- **A suite output field literally named `len` fails to compile on QB64.**
  `LEN` is a reserved QB64 builtin (string/array length) — same gotcha
  already called out in `test/conformance.test.js`'s `normalizeXAst`
  comment. `samples/math-demo.js` (the conformance fixture for this
  module) names that field `mag` instead.

## Motivation

v0.1.0 ships only the AST primitives (`num`, `v`, `add`, `mul`, `sub`, `div`, `neg`,
`letIn`, `select`, `cmp`, `outputs`, `call`, `emitAll`).  Consumers end up
re-implementing the same safe-math and vector patterns in every project that touches
3-D geometry.  v0.2.0 adds a **`math` utilities module** of pre-built DSL functions
that compose those primitives into the patterns everyone needs.

---

## New export: `require('exprforge/math')`

All helpers return exprforge AST nodes (the same type `num`, `add`, etc. return),
so they compose freely with any other builder call.

```js
const { safeDiv, dot3, len3, cross3, normalize3, clamp } = require('exprforge/math')
```

---

## API

### `safeDiv(numerator, denominatorExpr, fallback)`

Guard against division by zero.  Returns `numerator / denominatorExpr` when
`|denominatorExpr| > EPS`, otherwise `fallback`.

| Parameter | Type | Description |
|-----------|------|-------------|
| `numerator` | AST node | The value to divide |
| `denominatorExpr` | AST node | The divisor (evaluated at runtime) |
| `fallback` | AST node | Returned when divisor is near zero |

```js
// Example: safe-normalize x component
safeDiv(v('x'), len3(v('x'), v('y'), v('z')), num(0))
```

**Note:** The internal EPS check uses `0.000001`.  A future version may expose
`safeDivEps(numerator, denomExpr, fallback, eps)` for callers that need a different
threshold — do not add it in v0.2.0 unless a real consumer needs it.

---

### `dot3(ax, ay, az, bx, by, bz)`

3-D dot product: `ax*bx + ay*by + az*bz`.

All parameters are AST nodes.

```js
dot3(v('tx'), v('ty'), v('tz'), v('tx'), v('ty'), v('tz'))
// → tx² + ty² + tz²   (squared length)
```

---

### `len3(x, y, z)`

3-D Euclidean length: `sqrt(x² + y² + z²)`.

Parameters are AST nodes.  Emits a `sqrt` intrinsic (`Math.sqrt` in TS, `Sqr` in
QB64-PE).

```js
len3(v('dx'), v('dy'), v('dz'))
```

---

### `cross3(ax, ay, az, bx, by, bz)`

3-D cross product: returns `{ x, y, z }` as three AST nodes (a plain JS object, not
an AST node itself).

```js
const { x: kx, y: ky, z: kz } = cross3(
  v('t0x'), v('t0y'), v('t0z'),
  v('t1x'), v('t1y'), v('t1z'),
)
// Use kx, ky, kz as AST nodes in subsequent letIn calls
```

The return shape is `{ x: ASTNode, y: ASTNode, z: ASTNode }` so callers can
destructure and bind each component in a `letIn`.

---

### `normalize3(x, y, z, fx?, fy?, fz?)`

Safe-normalize a 3-D vector.  Returns `{ x, y, z }` (same shape as `cross3`).

When the vector length is below EPS, falls back to `(fx, fy, fz)`.  Default
fallback is `(0, 1, 0)` — forward-facing convention.  Pass `num(1), num(0),
num(0)` etc. to override.

```js
const { x: nx, y: ny, z: nz } = normalize3(v('dx'), v('dy'), v('dz'))
// fallback: (0,1,0) — safe for most path-tangent normalization
```

```js
// Custom fallback — if near-zero, default to +X
const { x, y, z } = normalize3(v('dx'), v('dy'), v('dz'), num(1), num(0), num(0))
```

---

### `clamp(val, lo, hi)`

Clamps `val` to `[lo, hi]`.  All parameters are AST nodes.  Emits as nested
`select` / `cmp` nodes — no runtime intrinsic required.

```js
clamp(v('t'), num(0), num(1))   // keeps t in [0, 1]
```

---

## EPS constant

```js
const { EPS } = require('exprforge/math')
// EPS = num(0.000001)
// Use this in your own cmp() calls for consistency with safeDiv / normalize3.
```

## What stays in user code

These helpers intentionally stay **out** of `exprforge/math` because they encode
project-specific conventions:

| Pattern | Reason to keep local |
|---------|----------------------|
| `nearVert` check (|ty| > 0.98) | Specific to one orientation convention |
| `degToRad` with baked-in PI | Trivial; baking PI is fine locally |
| Rodrigues transport | Too domain-specific for a general math lib |
| Gram-Schmidt frame | Specific to chosen worldUp convention |

---

## Implementation notes

- All helpers are **pure compositional functions** — they take AST nodes and return
  AST nodes.  No new emitter logic is needed; the existing `emitAll` pipeline handles
  them transparently.
- `cross3` and `normalize3` return **plain JS objects** `{ x, y, z }`, not AST
  nodes, so callers can destructure.  This is a deliberate ergonomic choice: forcing
  callers to name each component in a `letIn` keeps the generated variable namespace
  explicit.
- Add these to a new `math/index.js` inside the package and expose the require path
  via `package.json` exports:
  ```json
  "./math": "./math/index.js"
  ```
- No new dependencies.  The math module `require`s only the core exprforge builders.

---

## Breaking changes

None.  `require('exprforge')` is unchanged.  `require('exprforge/math')` is additive.

## Resolved (was "Open questions before cutting the release")

1. **Shared vs. per-component denominator in `normalize3`.** Implemented as
   recommended: a single shared denominator. `len3(x,y,z)` is computed once
   and shared across all three divisions, not three independent `safeDiv`
   calls each re-deriving the length.

   The mechanism this needed wasn't obvious from the recommendation alone:
   `normalize3` must return three *independent* `{x,y,z}` nodes (see below),
   but `collectLets` (`ast.js`) only allows one binding per name per
   function. The resolution is to let-bind the shared length inside just
   *one* of the three returned nodes (`x`) and have `y`/`z` reference that
   name bare — `collectLets` hoists the binding regardless of which sibling
   subtree it was found in (confirmed by `test/ast.test.js`'s "collectLets
   hoists a let nested inside one output field's own value"). A
   process-wide gensym counter keys the binding name so two `normalize3()`
   calls in the same function (e.g. normalizing two vectors) don't collide
   on a fixed name. See `math/index.js`'s `normalizeGensymCounter`.

2. **`cross3` return shape.** Object `{ x, y, z }`, as this doc's own
   Implementation Notes section already stated — not actually in tension
   with the "open question" framing above it, just an inconsistency in how
   this doc was originally written.

3. **`clamp`'s `select`/`cmp` expansion.** Confirmed against real usage
   elsewhere in the codebase (`samples/spline-frame.js`): `cmp(left, op,
   right)` and `select(cond, then, else)` with `<`/`>` string ops are
   exactly the existing API shape. No dedicated `clamp` intrinsic exists or
   is needed in any target emitter.
